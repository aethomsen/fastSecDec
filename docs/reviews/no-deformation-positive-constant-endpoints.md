# Positive-projective constant endpoint admission

This slice issues a genuine constant first-axis interval from an existing
`PositiveProjectiveCellMap`. It retains the original source owner, cell ordinal,
`RootBound`, distinct-root selector and named coordinate roles. It does not issue
later algebraic prefixes, transport that interval into a closed endpoint chart,
or complete the double-box atlas. `EndpointTransport` explicitly refuses this
new step until its root-equation inventory is extended.

The existing affine `RegularSection` admission is factored into a private
immutable payload behind sealed borrowed affine/positive geometry accessors.
All old affine public accessors and callback contracts remain. Both callers reuse
native root isolation, ordering/refinement, polynomial conversion, derivative and
endpoint domain certificates, and native certificate replay. No detached
polynomial or shape key can issue the positive owner. Constant root callbacks
retain a separate genuine source/selector contract and use the existing native
constant-function evaluator path rather than solving at every integration point.
The power map and its positive diagonal are exact; role freshness and unsupported
second-axis/transport cases remain explicit.

The degree-32 control exposed an independent existing callback preparation bug.
Symbolica's default `AtomField` enables `statistical_zero_test`, so the native
`coefficient_list` path can drop nonzero small exact dyadic coefficients. A focused
native probe reproduced 26/27 coefficients instead of 33 for two tight degree-32
brackets and a nonzero exact recombination residual. The public
`to_polynomial_in_vars_with_field` API with `statistical_zero_test: false`, followed
by native dense-univariate conversion, retained all 33 coefficients and exact
recombination. The production fix selects that exact field policy and retains
all degree, term, bit, workspace and recombination checks. No custom coefficient
extraction, differentiation, root algorithm or numerical approximation was added.
This fixes existing V3 preparation too; it does not claim to fix every later
numerical conditioning issue in shifted root evaluation.

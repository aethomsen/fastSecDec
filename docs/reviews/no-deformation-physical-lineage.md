# Original factors through repeated physical resolution

The new physical-state interface retains the actual marked source before its
first pivot and transports its keyed polynomials through subsequent issued
maps. The initial constructor consumes a native companion center and records
its source opening, frame and exceptional history. That opening is explicit;
it does not acquire coverage of the omitted ambient domain.

The existing two-map construction remains an adapter. Both entrypoints use the
same subsequent state, terminal checks and residual-restart rules. This removes
the fixed ancestry depth from original-factor transport without claiming a
complete global resolution driver.

## Exact transport and cycle ownership

Each original polynomial has a retained total pullback, accumulated exceptional
multiplier and current quotient. Native checked controlled transforms operate
on each keyed quotient. They do not look it up in a normalized generator list,
which can change coefficients or basis. A constant-multiple control preserves
the coefficient two when the current ideal normalizes `2*x` to `x`.

The same issued map transports all factors, exceptional equations and the full
coordinate Jacobian. Existing native ring extensions, membership, controlled
division, history and Jacobian primitives provide the arithmetic. Source-ideal
membership is prepared once per key batch through the existing caller-scoped
helper. No additional CAS or differentiation system is introduced.

Active companions and retired cycles have distinct lifetimes. A new positive
residual cycle requires completion of the active companion and a strict drop
of the complete component residual maximum. Its new source opening retains the
actual geometric history. The old companion is retained at its last admissible
frame; later centers must not continue to divide or transform it. Original
polynomials and the full Jacobian continue through every map.

One immutable retirement link is allocated at a checked cycle start and shared
by its siblings and descendants. Its references point backward; checked counts
prevent overflow. This avoids a copied retirement vector at every depth.

## Caller-owned progress and terminal authority

The caller-stepped physical chart frontier accepts an actual issued blow-up
with its initial problem, new-cycle start or active embedded presentation. It
inventories every issued chart and advances through original-factor transport,
component factorization and terminal verification. Unfinished work and accepted
receipts remain distinct. Resource refusal leaves the prior state available;
reissuing completed work does not perform another transformation.

Terminal verification remains per original factor: its residual quotient must
be a unit relative to the proved divisor form. Principalizing the ideal
generated by several factors cannot certify each of them. Terminal maps avoid
unnecessary contact/coefficient preparation; unresolved maps retain the actual
active hierarchy needed for continuation.

The frontier is currently resumable in memory. It adds neither durable proof
checkpoints nor a worker pool. Native algebra allocations and retained proof
trees still require caller budgets and measured process limits.

## Controls and remaining scope

The cubic control follows a retained branch of `z^2+x^3+y^3` through ten
third-step charts. Nine certify the original factors; the remaining chart has
five retained contact opens, four empty auxiliary loci and an actual monomial
center. All ten fourth-step descendants certify the original factors using
the same state API. Earlier unselected source charts remain in their owners;
this is not a completed global resolution.

The direct `x^2+y^3` control starts before the first pivot, proves a complete
residual-order drop from two to one, starts a new companion cycle and obtains
seven local terminal leaves. Retired-companion, constant-coefficient,
foreign-source and resource/retry controls test the ownership boundaries.

The harder `x^3+y^5` case retains an explicit native resource frontier. Its
child coefficient mark is six and maximum order ten. The coefficient
construction needs `lcm(1,...,10)=2520`, exceeding the default native
`Limits.max_mark=64`. The refusal is `coefficient mark LCM`; the accepted
ancestors and pending companion remain available. This is a configurable
resource limit, not mathematical non-resolvability. This milestone does not
raise it without degree, work and memory validation.

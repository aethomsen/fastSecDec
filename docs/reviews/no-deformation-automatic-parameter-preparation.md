# Automatic preparation of uniform parameter families

Native `threshold::generation::prepare` and its recovery path now reach the
previously explicit uniform-family issuer. The caller still declares runtime
parameters and exact strict chamber constraints. Bounded bracket discovery
proposes cylinders; native whole-domain sign and regularity certificates,
complete geometry and continuation admission decide whether they are valid.
Samples and successful numerical binding do not certify a chamber.

One shared route decision distinguishes historical fixed one-axis preparation,
fixed multidimensional cubes and the new uniform route. The latter supports
the already admitted native cube and one-axis affine-projective source. Only
integration variables receive unit coordinates or Jacobian widths. GCAD keeps
runtime variables in its prefix, including declared parameters used only by a
guard. Its supplied variable order must respect those roles.

The existing dyadic proposal search, native polynomial operations, topology
views and family issuers are reused. A private typed entry point preserves the
difference between a bracket/regularity miss and an immutable failure. Only a
genuine proposal miss tries another margin. Unsupported densities, invalid
parameters, native failures, cancellation and resource limits retain their
proper outcomes. No alternate algebra, chamber parser or numerical root
finder is introduced.

## Recovery and compatibility

Uniform preparation stores regular-family configuration version two. Version
one remains fixed-cube-only; historical one-axis configuration retains its
absent regular-family field. Actual old and new executables produce identical
configuration bytes and preparation identities for the fixed controls.

Recovery reconstitutes the native request and checks its route against the
saved version, runtime roles, sampled coordinates, source origin and
fixed-fiber policy. Missing capability, transplanted versions and incompatible
roles refuse. Both canceled raw-evidence recovery and completed recovery
reverify the saved decomposition without invoking Solve. A fresh child checks
symbol remapping after unrelated symbols have been registered. Original source
and prepared identities remain prerequisites for accepting compiled receipts.

HEPKit forwarding, the serial full-catalogue bound-point identity and their
execution matrix remain subsequent gates. Existing frontend refusals stay in

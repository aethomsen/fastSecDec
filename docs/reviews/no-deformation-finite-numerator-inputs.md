# Source-owned finite numerator coefficients and inputs

This slice connects original polynomial numerator factors to finite coefficients
on one relative boundary face. It preserves the genuine projective preparation,
native sector map and factor indices. It is not an all-face endpoint certificate
or a prepared integration kernel.

`SourceNumerators` deduplicates exact native numerator Atoms and freezes their
individual source-coordinate degrees before coefficient or epsilon
specialization. Symbolica's polynomial conversion uses an AtomField with
statistical zero testing disabled. Hidden dependence on a source coordinate
inside a coefficient receives an explicit refusal. Inactive factors retain
their original associations without an unnecessary degree calculation.

`NumeratorFace` uses those degrees to clear the coordinate-map denominators.
Only the small geometric expressions are expanded after resource preflight;
native rational-polynomial arithmetic proves the canonical numerator and
monomial denominator. The original bulk numerator stays compact. Native relative
series supply the extracted integer power and requested finite coefficients.
The clearing factor, residual direction denominator and term powers remain
inspectable. An incomplete or empty series is not accepted as an exact zero.
The admitted class currently requires normalized roots independent of the
chosen normal, including their actual coefficient-chart inputs.

Symbolic partial derivatives act only on retained independent source formals.
A derivative with respect to a replaced source coordinate must be taken before
pullback; an absent name cannot justify returning zero. Derivatives with respect
to physical unit coordinates also require the coordinate/root chain rule.

`CompiledFaceInputs` reuses Symbolica's native evaluator-composer dependency
pruning. It first selects the required finite source outputs under independent
original inputs, and only then binds the normal to its boundary value. Thus an
unused divergent ray is removed before evaluation. Straight-line instructions
are required because the adopted native optimizer does not perform this pruning
across control flow. Raw root formals in coefficient expressions remain outside
this first interface; roots reached through finite source coordinates retain
their actual normalized map, Scope and branch ownership.

Remaining direction inputs are strictly inside their relative unit face;
finite output coordinates may legitimately be zero. Native error tracking,
callback failures and caller-owned evaluation scratch are preserved. Pruning
dead instructions does not establish removable limits of retained singular
instructions. The complete open map continues to reject its ray endpoint.

Ten maintained native test groups pass on the reviewed source. They cover
exact geometry cancellation and nested complements, source-degree stability
under epsilon specialization, complete factor links, resource and foreign-owner
refusals, finite coefficients, and numerical evaluation at 128/256 bits.
Native codec restoration and uncertainty propagation are exercised with changed
inputs. A nonzero mixed derivative through the normalized root and actual
transport chart agrees with the independent value `-17/5`; it uses Symbolica
differentiation and function maps, without endpoint dual evaluation.
The raw-root rejection test uses a genuine issued face and a coefficient that
still contains its selected root; it checks the refusal before compilation.

The first physical-source run exposed an overly conservative multivariate
expansion estimate in the resource preflight. Symbolica collects one selected
variable while retaining its coefficient Atoms factored. An API/source/probe
audit found no preconversion bound for that operation. The replacement guard
therefore bounds only the supported selected-variable syntax; all retained
degrees and coefficients still come from native collection of the original
Atom. Checked counters bound support, expression nodes and pair operations.
General multi-term heap powers remain unsupported. These node estimates do not
bound integer bit storage or every internal native allocation.

With an explicit 64-million-node coefficient allowance and a 100 GB external
address-space limit, the actual physical source catalogue completes in
10.286 seconds with 41,144 KiB child peak RSS. It preserves all 156 factor links
and all 128 distinct numerator degree inventories; no full GCAD proof is read
again. An independent native diagnostic collects all 768 numerator/coordinate
combinations successfully. This measures source preparation and catalogue
construction, not complete generation, integration or convergence.

The final source extraction into `source/preflight.rs` changes only module
boundaries, imports and required visibility. Independent normalized-source
comparison verifies that the tested resource and test bodies are unchanged.
The combined workspace/all-target threshold build passes strict Clippy with
warnings denied; formatting and diff checks also pass after the extraction.

The root independently reviewed both implementation slices. A separate
generation reviewer checked the canonical-geometry correction. API, source and
focused native probes confirm that no alternate CAS, series engine, instruction
pruner, root solver or serializer is needed. Production execution consumes no
sampling RNG and owns no threads or processes. Root-dependent normals,
intersecting faces, uniform closed units and complete symbolic subtraction
remain explicit subsequent gates.

# Compiled regular families with runtime parameters

This increment connects a complete, uniformly admitted regular algebraic family
to the existing native compiler, detached worker jobs and indexed artifacts.
It does not infer a uniform family from a successful solve at one parameter
point. Native GCAD supplies the verified decomposition; the regular-family
issuer separately admits every cell's density, branches, widths, endpoint
powers and common meromorphic continuation throughout one parameter chamber.

## Representation and binding

Runtime parameters precede integration variables in the native CAD problem.
The explicit input-role map connects `[parameters, units]` in composed maps to
the existing `[units, parameters]` kernel convention. Parameter directions
contribute neither sampling coordinates nor Jacobian widths. The tests include
parameters outside the unit interval and two genuine integration directions.

The chamber's compact arithmetic guard uses Symbolica's rational evaluator.
Binding converts finite floating-point values to their represented exact
rationals and checks the original strict bounds, denominator conditions and
exceptional predicates. It does not rationalize values to a guessed simpler
number. All checks precede mutation of the existing parameter point and exact
offsets, so a rejected bind leaves the last valid state usable.

The guard's semantic identity covers canonical mathematical predicates and
parameter roles, independently of symbol registration order, optimized IR or
worker scheduling. Existing native codecs save the optimized guard program.
Binding and restoration do not solve GCAD again, reconstruct polynomials or run
Horner/common-subexpression optimization. A mutex protects only caller-used
rational evaluator scratch; the library starts no threads or processes.

The new explicit v18 sector payload and v4 indexed capability retain this guard
association, including exact/setup carriers and selectively loaded records.
Detached work and completion receipts must match their parent's guard as well
as its existing source and lineage identities. A parent reference cannot
transplant a guard from another template. Fixed v15/v16/v17 payloads and fixed
v3 archive layouts retain their existing representations.

Preparation writes one shared guard record and drops the full geometry owner
before caller-owned compilation jobs run. Weak-owner assertions exercise that
release. This is an ownership check, not an aggregate RSS measurement or a
claim that global CAD preparation has sector-bounded memory.

## Scientific and compatibility evidence

The compiled control uses `F=y^5+y-p+2`, with `9/4 < p < 5/2`, and retains the
full complex Laurent vector through epsilon order one. It rebinds the same IR
at `p=2.375`, `2.4`, `2.3125` and back to `2.375`; the nonbinary value exercises
faithful floating-point admission. Independent native exact root isolation
checks the finite imaginary contribution. A parameter-dependent numerator
and prefactor are compared with independently prepared exact fixed fibers.

The QMC test compares resident/detached setup crossed with resident/selected
record execution at two parameter points: eight runs of 2,048 accepted rows.
For each point the four lanes retain identical six-component estimates,
uncertainties and all 36 covariance entries, including checkpoint restoration.
These lanes are native execution tests, not a claim that the automatic CLI
implements every parameterized generation/integration combination. The
selected execution lanes share one detached indexed archive.

Fresh compiler and loader processes deliberately register unrelated symbols
first. They import the saved work or kernels without a retained GCAD owner,
exercise rebinding and rejection, and preserve full/selected/exact-only scope.
Malformed tests cover missing or transplanted guards, mismatched parameter
roles, incompatible receipt versions and altered parent associations.

An independent compatibility audit reads five old fixtures with the new
default-native library: a freshly emitted v15 control, historical v16,
historical eager and SymJIT v17, and a shifted-root v17 control. Every vector,
order, offset, identity and scope matches its baseline, before and after
resaving. Conversely, an actual old consumer rejects the new v18 payload,
v4 archive and parameterized lineage instead of silently ignoring their new
capability. These tests use actual serialized objects, not downgraded headers.

## Native reuse and remaining work

API, source and executable controls reuse native rational conversion,
polynomial domains, exact predicates, evaluators, implicit root derivatives,
symbolic endpoint subtraction and codecs. No alternate CAS, root finder, AD,
physical graph or estimator was introduced. The composed moving-root tests
include degrees five and seven; the existing regular-section controls also
cover degrees eleven and seventeen. Higher polynomial degree alone does not
require radicals or expansion of the full pulled-back integrand.

This issuer currently requires a single admitted parameter chamber with
supported linear parameter bounds and uniformly regular root sections.
Colliding roots, changing degree, a general singular algebraic atlas and
auxiliary-regulator cancellation remain part of the unfinished general
resolver. A parameter-dependent prefactor must currently be a finite
polynomial; a parameter-independent meromorphic factor such as `Gamma(epsilon)`
is supported, but the mixed `p*Gamma(epsilon)` path still refuses explicitly.
Parameter-dependent endpoint exponents are also outside this issuer.

The native compiled-family API is the delivered boundary here. Automatic
projective physical-bubble preparation, CLI chamber settings and thin HEPKit
parameter forwarding require their own complete physics and interface gates.
The existing frontend refusal is retained until those gates pass. Neither
this increment nor the higher-degree regular controls complete the active
no-contour plan.
